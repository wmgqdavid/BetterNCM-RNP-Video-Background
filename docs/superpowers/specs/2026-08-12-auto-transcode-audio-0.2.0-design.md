# RNP Video Background 0.2.0 自动转码与背景声音设计

日期：2026-08-12  
状态：用户已授权全自动方案并要求持续制作至成品  
适配基线：Windows x64、BetterNCM、RefinedNowPlaying Next 3.0.2

## 1. 目标

在保持 0.1.2 背景层与 RNP 功能完整性的基础上，增加：

1. 选择视频后自动检测编码、分辨率、帧率和文件大小。
2. 对不兼容或明显过重的视频自动转换与压缩。
3. 首次使用时引导安装独立 FFmpeg 组件，不把大型二进制塞入商店插件包。
4. 国内镜像优先、GitHub 备用、离线包导入兜底。
5. 用户可选择背景视频声音和独立音量。
6. 背景视频与网易云音乐同步暂停/继续；切歌时连续播放，不重置进度。

## 2. 方案比较与选择

### 方案 A：轻量插件 + 独立 FFmpeg 组件（采用）

- 插件负责检测、设置、状态和播放。
- 独立组件负责 ffprobe 与 FFmpeg 转码。
- 主下载源使用国内 npmmirror，GitHub 为备用，离线导入为兜底。
- 优点：商店插件小、转码可靠、可显示进度、可升级组件。
- 代价：首次使用需要用户确认安装组件。

### 方案 B：只调用系统已有 FFmpeg

- 插件最轻，但大量用户没有 FFmpeg，需要自行安装和配置。
- 不符合“一键自动”的目标，因此不采用。

### 方案 C：FFmpeg 随 `.plugin` 分发

- 用户体验直接，但插件包会增大几十到上百 MB。
- 原生应用必须完全开源并由 GitHub Actions 构建，商店审核和更新成本更高。
- 不采用。

## 3. 安全与分发边界

### 3.1 用户授权

- 选择普通兼容视频不需要安装组件，直接播放。
- 当文件需要检测或转码而组件不存在时，设置页显示安装说明。
- 下载和执行原生组件前必须获得一次明确用户确认；不静默安装。
- 用户已要求“全自动转换”，指组件安装完成后的检测与转码全自动，不取消首次原生组件授权。

### 3.2 下载源

顺序：

1. 固定版本的 npmmirror CDN。
2. 固定版本的 GitHub Release。
3. 用户手动选择离线组件压缩包。

每个下载源必须对应同一版本和同一 SHA-256。下载到临时文件后先校验，再解压到插件数据目录；校验失败立即删除临时文件并停止安装。

### 3.3 许可证

- 组件页公开 FFmpeg 版本、构建来源、许可证、源码链接和 SHA-256。
- 辅助程序源代码进入公开仓库。
- 若辅助程序属于 BetterNCM 上架准则中的原生应用，使用 GitHub Actions 可复现构建。

## 4. 组件架构

### 4.1 插件层

职责：

- 本地视频选择与设置持久化。
- 调用辅助程序的结构化命令。
- 展示组件状态、媒体信息、转换进度、取消和错误。
- 转换成功后自动把背景源切换为输出文件。
- 背景声音、音量、播放同步和连续播放。

### 4.2 辅助程序

职责：

- `doctor`：返回组件与 FFmpeg 版本。
- `probe`：调用 ffprobe，输出单行 JSON 媒体信息。
- `transcode`：调用 FFmpeg，按固定安全参数转码，并输出 JSON Lines 进度。
- `cancel`：终止当前转码进程。
- 不访问网络；下载由插件或安装器负责。

输入参数必须使用参数数组传递，不拼接 shell 命令。输出路径、源路径和临时路径必须标准化，禁止覆盖源文件。

## 5. 检测与自动转换规则

### 5.1 可直接播放候选

满足以下条件时先尝试直接播放：

- 容器为 MP4/M4V 或 WebM。
- 视频为 H.264/AVC、VP8 或 VP9。
- 像素格式是常见 8-bit 兼容格式。
- 分辨率不高于 1920×1080。
- 帧率不高于 60 fps。

直接播放仍以浏览器 `loadeddata/canplay` 为最终依据。解码失败时进入自动转换。

### 5.2 必须转换

任一条件成立：

- HEVC/H.265、AV1 或未知视频编码。
- 分辨率高于 1920×1080。
- 帧率高于 60 fps。
- 像素格式或位深可能不受 CEF 支持。
- 浏览器报告解码失败或格式不支持。
- 用户点击“重新压缩当前视频”。

### 5.3 仅建议压缩

文件较大但编码兼容时不强制转码，避免无谓画质损失；设置页提供压缩按钮。全自动模式只针对兼容风险和超规格媒体。

## 6. 转码参数

默认输出：

- 容器：MP4。
- 视频：H.264/AVC，`yuv420p`。
- 分辨率：最长边不超过 1920×1080，保持比例且保证偶数尺寸，不放大小视频。
- 帧率：不超过 30 fps。
- 质量：CRF 23。
- 编码速度：`medium`；若性能检测不足可使用 `fast`。
- Web 优化：`+faststart`。
- 输出文件名：`原名.rnp-compatible.mp4`；冲突时增加序号。

声音关闭时：`-an`，移除音轨。  
声音开启时：AAC-LC，128 kbps，立体声。

输出先写入同目录的临时文件，成功且可探测后原子重命名；失败或取消清理临时文件。原视频永不修改或删除。

## 7. 背景声音与播放同步

新增设置：

```text
videoAudioEnabled: false
videoVolume: 0.35
syncWithMusicPlayback: true
```

- 默认静音，避免叠音和自动播放限制。
- 开启声音后显示独立音量滑块，不改变网易云音量。
- 第一次带声音播放若被浏览器阻止，等待用户在播放页点击一次。
- 网易云暂停时视频暂停；继续时从原位置继续。
- 切歌不改变 `currentTime`，视频连续播放。
- 离开 RNP 播放页时暂停，返回时继续原位置；更换视频或转换输出才重置。

同步信号优先使用网易云播放器的播放状态/API；无法可靠获得时观察主音频元素和播放按钮状态，变化去抖。

## 8. 转换流程

```text
选择视频
  → 组件可用？
      ├─ 否：先尝试直接播放
      │      └─ 解码失败：提示并请求安装组件授权
      └─ 是：probe
              → 兼容：直接播放
              → 不兼容：自动开始 transcode
                         → 显示进度/取消
                         → 成功后 probe 输出
                         → 自动切换背景源并保存新路径
                         → 失败时保留原选择和 RNP 原背景
```

安装授权完成后，用户以后选择不兼容视频无需再次确认转码。

## 9. 状态与错误处理

状态：`idle`、`probing`、`needs-component`、`installing`、`transcoding`、`ready`、`error`、`cancelled`。

- 下载失败：依次切换下载源，最后提供离线导入。
- SHA-256 不匹配：不得执行，明确提示安全校验失败。
- 磁盘空间不足：转码前估算并阻止启动。
- 输出目录不可写：提示选择其他输出目录。
- 转码失败：显示简化原因并保留诊断日志路径。
- 取消：终止子进程并清理临时文件。
- 插件卸载不自动删除用户转码输出；组件可在设置页单独卸载。

## 10. 设置界面

新增三个区域：

1. 媒体信息：编码、分辨率、帧率、大小、兼容结论。
2. 自动转换：组件状态、安装/离线导入、进度、取消、重新压缩。
3. 背景声音：启用开关、独立音量、与音乐同步说明。

保留 0.1.2 的视频选择、填充、亮度和精简播放控件。

## 11. 测试与验收

### 自动化

- 设置迁移默认静音、音量 35%、同步开启。
- 参数生成覆盖静音/有声、4K、60fps、HEVC、兼容 H.264。
- 输出永不等于源路径。
- 下载源顺序与固定 SHA-256 校验。
- JSON 协议、进度解析、取消和错误码。
- 播放暂停/继续同步，切歌不重置 `currentTime`。
- 继续保护 RNP 设置、全屏、歌词和交互功能。

### 本机端到端

- 兼容 H.264：不转码，直接播放。
- HEVC 4K60：自动转为 H.264 1080p30 并切换。
- 静音转换：输出无音轨。
- 有声转换：输出 AAC，音量可调。
- 暂停/继续同步，切歌连续播放。
- 取消转码不留下可见的损坏输出。
- 国内源失败时切换 GitHub；双源失败时离线导入可用。

## 12. 实施分期

为降低商店审核和回归风险，0.2.0 分为同一项目内的两个可独立验证单元：

1. 辅助程序、探测、转码与组件安装。
2. 插件界面、声音和播放同步。

只有两部分全部通过端到端验证后才发布 0.2.0。现有 0.1.2 包保留为回退版本。

## 13. 自检结论

- 需求、默认值、分发源、失败回退和许可证边界明确。
- 原生组件首次安装仍需要明确授权，不与“之后不再询问”冲突。
- 不覆盖原视频、不静默执行未校验二进制。
- 自动转换范围限制在兼容风险，避免所有大文件无条件重编码。
- 视频播放职责与转码职责隔离，可分别测试和回退。
